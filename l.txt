Замедление загрузки происходит по двум причинам:
1. **Отсутствие индекса в базе данных (главная причина)**. По мере роста базы данных таблица `snapshot_songs` разрастается до сотен тысяч строк. Если в ней нет индекса по полю `snapshot_id`, СУБД SQLite при каждом запросе дашборда вынуждена перебирать всю таблицу целиком с самого начала.
2. **Зависимые подзапросы (correlated subqueries)**. Наш предыдущий SQL-запрос выполнял сложную группировку строк через `COUNT(DISTINCT ...)` отдельно для каждого из 25 пользователей. Это заставляло базу делать полный перебор строк десятки раз за один запрос.

Мы решим эту проблему двумя шагами, что ускорит загрузку дашборда с нескольких секунд до **5–20 миллисекунд**.

---

### Шаг 2. Создание индекса в базе данных (Критически важно!)

Чтобы бэкенд перестал выполнять "тяжелое" сканирование всей таблицы `snapshot_songs` при каждом поиске песен снапшота, обязательно добавь индекс на внешние ключи.

Выполни эту команду в консоли своего проекта (замени `<ИМЯ_БАЗЫ_ДАННЫХ>` на имя твоей D1 базы из wrangler.toml):

```bash
npx wrangler d1 execute <ИМЯ_БАЗЫ_ДАННЫХ> --remote --command "CREATE INDEX IF NOT EXISTS idx_snapshot_songs_snapshot_id ON snapshot_songs(snapshot_id);"
```

*(Если ты тестируешь локально, выполни ту же команду без флага `--remote`).*

Также для идеальной производительности очень рекомендуется создать аналогичные индексы для связей снапшотов с пользователями, если они еще не созданы:
```bash
npx wrangler d1 execute <ИМЯ_БАЗЫ_ДАННЫХ> --remote --command "CREATE INDEX IF NOT EXISTS idx_snapshots_user_id ON snapshots(user_id);"
```

Эти два шага моментально решат проблему с долгой загрузкой страниц!
